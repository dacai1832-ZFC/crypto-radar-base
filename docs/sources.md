# 信源类型学与选源纪律

> 只描述信源**类型**与选源原则。具体厂商名单、观察清单、频道清单属核心信源
> 选择，全部在私有仓与本地配置中，不公开。

## 使用的信源类型

| 类型 | 用途 | 门槛 |
|---|---|---|
| 公共链上数据（节点 RPC） | 候选池发现、仓位/流动性核验 | 无 key，公共端点 |
| 免费安全评分聚合 API | 新代币风险信号（合约/持有人/流动性） | 无 key 档位 |
| 免费社区声量端点 | KOL 声量、smart followers 异动旁证 | 免鉴权公开端点 |
| 免费投资情报 API（免费档） | 项目/机构档案、融资背景、月度配额内详情 | 注册制免费 key |
| 即时通讯频道官方 API（规划中） | 一级情报频道旁证 | 官方账号 API |

## 选源纪律

1. **免费优先**：优先无 key / 免费档；付费信源必须论证不可替代性并设预算护栏；
2. **stdlib 可达**：信源接入必须纯标准库可实现（零第三方依赖红线）；
3. **失败不当负面**：信源缺席/失败如实缺席，绝不把「拿不到」当「信号差」；
4. **退出码恒 0**：快照类采集任何失败都不炸管线；
5. **计费护栏强制**：按命中计费的信源，双重预算护栏（见 infra-patterns §5）；
6. **非官方端点要可替换**：社区逆向端点封装成独立模块，预留同构 swap-in 点；
7. **官方条款优先**：平台型信源遵守其服务条款（限速信号、数据用途边界），
   防封号优先于采集量。

## 明确不做的

- 不用需要登录态/加密破解的网站接口（维护成本与封控风险远超价值）；
- 不接已停服/不稳定的免费源（定期体检信源健康度，死了就下架）；
- 不把信源原始数据直接当结论——所有旁证进日报前都要过判定层。
