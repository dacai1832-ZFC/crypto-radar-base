# 基础设施模式

> 描述这套系统依赖的几类通用工程模式。只讲设计与取舍，不给实现。

## 1. 状态持久化：Release 资产作状态载体

无服务器的定时管线需要一个「运行间记忆」。本系统不用外部数据库/缓存服务，
而是把状态（数据库 + 运行记录）打包成仓内 Release 资产：

```
班次开始：下载最新 Release 资产 → 解包到工作区
班次结束：重新打包 → 上传为新 Release 资产（原子替换）
```

取舍：不引入任何常驻服务；代价是每班多了约 1 分钟的存取，可接受。

## 2. 水位线断点续跑

云端定时器有分钟级抖动，也可能整班错过。采集端按**水位线**（上次处理到的位置）
增量推进：重启无缺口、重跑不重复。错过的时间片由下一班自然补齐，无需追赶逻辑。

## 3. 调度形态：双班制 + 不重叠并发

- 每日固定两班（早班含推送，晚班纯采集），而非高频轮询——
  在免费额度（私有仓每月有限 Actions 分钟数）内留足余量；
- `concurrency` 组锁防重叠：上一班没跑完时下一班排队而非并行；
- 周度 keepalive 提交，防仓库长期不活跃被平台自动停用调度。

## 4. HTTP 纪律：退避 + 限速 + 信封归一

- 指数退避重试（1s → 2s → 4s），穷尽即放弃并如实记录，绝不无限重试；
- 全局最小调用间隔，给远端限速阈值留余量；
- API 响应统一过「信封归一」层：成功 / 权限边界（套餐不含该端点→同轮短路，
  不再打网络也不误报故障）/ 未命中（常态，非故障）/ 其余错误，四态分明。

## 5. 计费信源的双重预算护栏

按命中计费的信源（每次成功查询扣额度池）必须同时满足：

1. **本地预算上限**：单班消费封顶，超限即停取；
2. **远端余额感知**：先查余额，预算取 `min(本地上限, 远端余额)`，
   不把月度池子花穿。

## 6. 零网络离线测试范式

所有采集/快照脚本的网络层与时间层（urlopen / sleep）做成可注入，
测试用假回放序列覆盖：成功、退避后成功、权限边界、未命中、预算耗尽、
缺凭据跳过——整条测试零真实网络、秒级跑完。

## 7. Secret 卫生

凭据只走环境变量 / 平台 Secrets 注入；代码、日志、产物、提交记录零出现；
脚本在缺凭据时**整体跳过并退出 0**（降级而非故障）。
